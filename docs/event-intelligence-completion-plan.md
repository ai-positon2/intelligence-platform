## Part 1 implementation

Candidate discovery followed by unfinished verification is now partial research, including when zero events survive. Reports say failed searches returned no usable result rather than asserting they never ran. Incomplete output leads with a provisional headline, and an empty partial run does not claim an empty market. Discovery and confirmation prompts stop when sufficient evidence exists instead of encouraging budget exhaustion. Regression cases preserve true-empty versus unfinished distinctions. Coverage improvement and provider savings must be measured in Part 3; these changes do not establish a recall increase by themselves.

## Part 2 implementation

Source admission now normalizes Unicode/punctuation and “&”/“and”, strips matching year suffixes and explicit parenthesized acronyms, and preserves regional qualifiers and conflicting years. Event names must precede the supported date range locally; another intervening event sentence or a name appearing only in a link destination is insufficient. Common shared-year cross-month ranges are supported. Fragment duplicates no longer consume the second source slot.

Access checks retain individual observations. Explicit hotel/VIP inventory restrictions do not establish whole-event closure when the same page explicitly says general admission or event registration is open. Otherwise access remains unresolved. Application requirements and approval conditions are not treated as confirmed client eligibility. A later event-wide cancellation still blocks admission. Dynamic fallback reads retain hashes and read-mode metadata, without being promoted to rendered-page evidence.

These are deterministic literal-support checks, not semantic proof or browser rendering. Unsupported layouts, formats and ambiguous access remain unverified. Part 3 must measure the resulting coverage and factual accuracy; the bounded organizer challenge check is not the complete benchmark.
